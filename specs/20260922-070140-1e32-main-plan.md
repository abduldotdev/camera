## Approach
This plan implements the camera controls enhancement, zoom-slider mouse-wheel multiplier, and safe in-popup live preview sequentially across `CameraPopup.qml`, `Widget.qml`, and supporting tests/documentation. We avoid introducing unnecessary model abstractions or artificial constants: existing `Model.js` commands (`buildFovSetCommand`, `buildFovListCommand`) already correctly issue real `cameractrls -d <dev> -c logitech_brio_fov=<val>` commands, and existing `CameraSegmented` bindings already track and reflect selection. For the Digital Zoom slider, we introduce a targeted mouse-wheel multiplier on `CameraSlider` that intercepts wheel events without altering drag granularity, keyboard stepping, or other sliders. For the live preview, we use native `QtMultimedia` (`Camera`, `CaptureSession`, `VideoOutput`) inside `CameraPopup.qml` with strict on-demand V4L2 lifecycle management that activates only when open and idle, releases immediately on popup close, gracefully displays five mutually exclusive stream states (Active, Disconnected, Busy, Permission Denied, Generic Unavailable), and preserves full control availability at all times.

## Risks
- **V4L2 device lock contention (`EBUSY`)**: If `/dev/video0` is not released promptly when the popup closes, external conferencing applications (Meet, Zoom, Teams) cannot open the camera. *Detection & Mitigation*: Step 2 strictly binds deactivation to `onOpenChanged` so closing the popup immediately sets `camera.active = false`; verified by checking that no file descriptor remains open after popup close.
- **Multiplier leakage to other controls**: If mouse-wheel scaling is applied at the component level without gating, color/focus/pan sliders would exhibit erratic jumps. *Detection & Mitigation*: Default `wheelMultiplier` to 1 on `CameraSlider` and set to 10 strictly on the Digital Zoom instance; verified by code inspection and `qmllint`.
- **UI freeze on camera error**: If `QtMultimedia` encounters pipeline failure or permission rejection, an uncaught error could disrupt the UI event loop. *Detection & Mitigation*: Preview errors are handled declaratively via visual state overlays without affecting the sibling control tree, keeping controls completely non-blocking.
